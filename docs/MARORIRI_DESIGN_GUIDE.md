## 5. 残すもの・調整するもの・変更するもの

| 区分 | 対象 | 理由 |
|---|---|---|
| 残せるもの | CSS変数(トークン)による設計手法そのもの | 命名パターン・管理方法として合理的で、色の値だけ差し替えれば流用できる |
| 残せるもの | header/footerのセマンティックな構造 | クラス名・構造とも標準的で、MARORIRIのナビ項目(仕様書4番)に差し替えるだけで対応できる |
| 調整して残せるもの | 生成り系の背景色(`--bg`)の明るさ・トーン | 「落ち着き」という印象には合うため、微調整のうえアクセント(赤系)との相性を見て残せる可能性がある |
| 調整して残せるもの | 日本語本文フォント(Noto Serif JP) | 読みやすさ重視なら継続候補になり得るが、長文の読みものページとの相性は要検討(10番) |
| 変更した方がよいもの | ロゴ(名称・植物モチーフ) | 名称が旧ブランドのままであり、植物・根のモチーフは「スピリチュアルサービス」に近い印象を与えかねず、MARORIRIの位置づけと合わない |
| 変更した方がよいもの | アクセントカラー(茶色) | 今回の方針(赤系アクセント)と一致しないため |
| 変更した方がよいもの | 英字フォント(Cormorant Garamond) | 装飾的なセリフ体で、実務・判断力を伝える方向とはやや温度差がある |
| 変更した方がよいもの | 水彩・植物系のビジュアルモチーフ全般 | 本プロジェクトの初期段階(旧本来面目らぼの刷新方針)ですでに不使用の方針が確定している |

## 6. デザイン方向案A

**「墨と朱、実務書類のような落ち着き」**

- ニュートラル(チャコール・オフホワイト)を主役にし、赤は最小限の範囲(CTA・小さな強調)にのみ使う「抑制型」。
- 見出し・本文は濃いチャコールで統一し、赤に頼らず情報の階層を作る。
- 罫線・余白・背景トーンの切り替えで区切りを作り、装飾的な図形はほぼ使わない。
- 「実務の中で交わす書類・メモ」のような、静かで機能的な印象を目指す。

## 7. デザイン方向案B

**「朱印帳、和のニュアンスを残す実務デザイン」**

- 案Aと同じくニュートラル中心だが、見出し下の細い罫線や小さなアイコンに、朱色(印章のような深い赤)をやや広めに使う。
- 「和」のニュアンスをほんのり残し、既存サイトが持っていた落ち着いた雰囲気との連続性を意識する。
- 赤の使用範囲が案Aより広い分、扱いを誤ると伝統工芸系・和風テンプレートのような印象になりやすい。

---

## 8. 推奨するデザイン方向

**案Aを推奨する。**

理由: 赤の使用範囲を意図的に絞ることで、「セール」「警告」「情熱的すぎる」「女性的すぎる」という、避けるべき印象に振れるリスクを最小限にできる。ニュートラル(チャコール系)を主体にすることは、既存サイトが持っていた「生成り+落ち着いた色」というトーンからの連続性も保ちやすい。案Bのような赤の広い使用は、MARORIRIが避けたいとする「大規模ITコンサル」「派手な制作会社」ではない方向には合うが、代わりに「和風・伝統工芸」という新たな偏りを生むリスクがあるため、今回は採用しない。

## 10. タイポグラフィ候補

**比較**

| 案 | 特徴 |
|---|---|
| 既存継続(Noto Serif JP中心) | 既存ブランドとの視覚的連続性があるが、明朝体は画面上の長文可読性でゴシック体にやや劣り、読みもの記事本文・料金表・フォーム等の「読み取りやすさ」重視の要素との相性がやや弱い |
| ゴシック体中心へ変更 | 判断材料を読ませる実務サイトとして可読性が高いが、既存ブランドとの連続性は失われる |

**推奨**: 本文はゴシック体(可読性優先)、見出しにのみ明朝体(Noto Serif JP系)を残す、というハイブリッド案。「判断を任せられる」「説明が明確」という印象を本文の読みやすさで支えつつ、見出しに明朝を残すことで既存ブランドとの完全な断絶を避ける。

| 用途 | 方向 |
|---|---|
| 本文フォント | ゴシック体(和文)を新たに採用する方向で検討 |
| 見出しフォント | 既存のNoto Serif JP系(明朝)を継続する方向で検討 |
| 英字・数字 | 日本語フォントの内包英数字に頼らず、数字の桁が揃う欧文フォント(等幅数字)を別途指定する方向 |
| 料金表示の文字 | 数字を大きめ・太めにし、「円」「税込」等の単位は小さめにして視認性を優先。装飾書体は使わない |
| 読みもの記事本文 | 本文と同じゴシック体、行間・文字サイズを長文向けにやや広めに取る |
| コーダー部のコード表記 | 等幅(モノスペース)フォントを使用し、コードであることが一目で分かるようにする |

**表示速度への配慮**: 日本語Webフォントはファイルサイズが大きいため、新規に追加する場合は使用するウェイト(太さ)を絞り、システムフォントとのフォールバックを用意する方針とする(具体的なフォント名・読み込み方法は次回)。

## 11. 余白とレイアウト

`MARORIRI_WIREFRAME.md`6番(共通レイアウトのルール)、`MARORIRI_SUBPAGE_WIREFRAME.md`6番の内容をデザインの前提として踏襲する。

- セクション間の余白は「大・中・小」の3段階で統一し、ページごとにばらつかせない。
- コンテンツ最大幅と、本文の読みやすい幅は別々に管理する。
- 見出し階層は3段(ページタイトル・セクション見出し・小見出し)を基本とする。
- 丸みの強い装飾カードを大量に並べない方針を、デザイン段階でも継続する。

## 12. 見出しルール

| 種類 | 方向 |
|---|---|
| ページタイトル(H1) | 明朝体、サイズを最も大きくする |
| セクション見出し(H2) | 明朝体、ページタイトルより明確に小さくする |
| 小見出し(H3) | ゴシック体でもよい(本文との連続性を優先) |
| 補足見出し(FAQの質問文、カード内ラベル等) | ゴシック体、太さで区別する |

**英字の装飾**: 既存サイトにあった「見出し+小さな英語サブタイトル」(例:「― Three threads, one philosophy.」的な処理)は、多用しない方針とする。「過度に飾られていない」という要求と照らすと装飾に分類されるため、トップページなど限定的な箇所にのみ、決まったパターンとして残すかどうかは次回判断とする。

**下線・罫線**: 見出し自体への下線装飾は基本的に使わず、セクションの区切りは罫線・背景色の切り替えのみで表現する(既存ワイヤーフレームの方針を継続)。

## 15. 料金・表のルール

価格だけが強く目立ちすぎないよう、次の順で構成する。

1. 含まれる内容(価値の説明)
2. 価格(数字を大きめ・太めに、単位は小さく)
3. 個別見積もりとなる内容(除外事項は最後)

`55,000円(税込)`・`月額55,000円(税込)`・`月2回・各60分`は、常にこの表形式(項目/内容の2列、`MARORIRI_SUBPAGE_WIREFRAME.md`5番)で統一する。コーダー部の料金一覧(月額3,300円+追加メニュー3種)も、価格をカード装飾で目立たせすぎず、簡潔なリスト形式にする。

## 18. 写真・図版の方針

**比較**

| 案 | 特徴 |
|---|---|
| 写真中心(人を見せる) | 信頼感は出るが、大規模B2Bコンサル・派手な制作会社的な印象に寄りやすい |
| 抽象図版・簡単な関係図中心 | 「判断・整理」という行為を視覚化しやすいが、抽象度が高すぎると内容不明瞭になるリスクがある |
| 写真と図版を必要な箇所だけ併用 | ページの性質に応じて使い分けられる |
| 画像を極力減らし文字と余白中心 | 実装コストが最小で「説明が明確」という方針と相性がよいが、視覚的な差別化は弱くなる |

**推奨**: 「写真と図版を必要な箇所だけ併用する」案。信頼感が必要な要素は人物(プロフィール)に集約し、それ以外のページは説明の明確さを優先して画像を必須にしない。

### ページごとの画像有無

| ページ | 方針 |
|---|---|
| トップページ | ファーストビューに抽象図版を1点のみ |
| 1日WEB担当者 | 図版なし。WEB担当者メモは簡易アイコン枠のみ |
| 月額Web担当サポート | 確認サイクルの簡易図を1点(検討・必須ではない) |
| 対応できること | 領域が重なる抽象図を1点 |
| プロフィール | 人物写真(未定の場合はプレースホルダー) |
| マロリリコーダー部 | 図版なし。文字中心の読み物として構成 |
| 読みもの | 記事サムネイルは任意・小さく。一覧全体を画像中心にしない |

### 図版候補の必要性

| 候補 | 判断 |
|---|---|
| 発注側・MARORIRI・制作会社の関係図 | 保留(テキストで説明可能、優先度低) |
| 状況確認から担当整理まで(6行動) | 図版ではなくレイアウト(非直線グリッド配置)で代替、独立図版は不要 |
| 月額サポートの確認サイクル(5行動の循環) | 優先度中。あれば理解を助けるが、シンプルな枠+ラベルでも代替可 |
| 1日と月額の時間の使い方 | 不要。単位表記(/1回・/月)+カード比較で十分 |
| 対応できる範囲と専門会社へ任せる範囲 | 不要。2列レイアウトで十分 |

抽象的な人物イラストや、よくあるビジネス写真(握手・会議室等のストックフォト)は使用しない。
