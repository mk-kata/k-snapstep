## 9. サイト名の見せ方

`K-SNAPSTEP`だけではサービス内容が伝わりにくいため、ヘッダー・ファーストビューで肩書きと組み合わせる。

| 案 | 見せ方 | 評価 |
|---|---|---|
| 案1 | K-SNAPSTEP / 小さな会社の外部Web担当者 | サイト名を先に見せ、肩書きで補足する。ブランド名を主役にしたい場合に合う |
| 案2 | 小さな会社の外部Web担当者 / K-SNAPSTEP | 何をする相手かを先に伝え、名前は後から知ってもらう。初見の理解を最優先する場合に合う |
| 案3 | K-SNAPSTEP / 片山まゆみ｜小さな会社の外部Web担当者 | 屋号・個人名・役割の3つを一度に見せる。情報量が多く、ヘッダーのような小さな面には収まりにくい |

**推奨**: 案1。ヘッダーでは「K-SNAPSTEP」という名前を主役にしつつ、すぐ下に小さく「小さな会社の外部Web担当者」という役割を添えることで、名前と役割の両方を短い接触時間で伝えられる。案2は「対象者へのメッセージ」としてはファーストビューの見出し(`KSNAPSTEP_SITE_SPEC.md`10番の確定コピー)がすでにその役割を担っているため、ヘッダーで重ねて逆順にする必要は薄い。案3はヘッダーには情報過多なため、プロフィールページなど個人名を強調したい場所限定で検討する。正式決定はしない。

## 10. デザイン方向案A

**「墨と朱、実務書類のような落ち着き」(K-SNAPSTEP向け調整)**

- チャコール・生成りを中心にし、赤はCTAや重要箇所だけに絞る
- 罫線と余白で情報を整理し、装飾を抑える
- 見出しの一部に明朝体を残し、長年の経験・落ち着きを表す
- 全体として「積み重ねてきた経験の重み」を軸にした、回顧的なトーン

---

## 11. デザイン方向案B

**「外部Web担当者の実務ノート」**

- 白または薄いグレーを中心にした、より明るくクリーンな下地
- 濃い文字色、深い赤・えんじをアクセントにする
- ゴシック体を中心にし、確認・整理のテンポの良さを表す
- 見出しやラベルに、実際に確認作業をしているような小さな「ラベル」「チェック」的な視覚装置を使う(装飾的な罫線ではなく、状態や区分を示す実務的なラベル)
- 書類的になりすぎず、制作会社サイトにもコンサルサイトにも寄せない
- 全体として「今まさに状況を整理している」という現在進行形のトーン

**2案の違い**: 案Aは「経験の蓄積・歴史」を軸にした回顧的なトーン(明朝体・墨のイメージ)、案Bは「今まさに整理してくれている」という機能的・現在進行形のトーン(ゴシック体・ラベル/メモ的なUI)。単なる配色の違いではなく、時間軸の捉え方(過去の実績を見せるか、今の対応力を見せるか)が異なる。

---

## 12. 推奨する方向

**方向案Bを推奨する。**

理由: 3番で新たに明記された「和風すぎる」という回避対象に対し、方向案Aの明朝体・墨のイメージは、意図せず和風・書道的な印象へ寄りやすいリスクがある(旧`MARORIRI_DESIGN_GUIDE.md`7番で検討した「案B(朱印帳)」を今回あらためて避けたい方向とも重なる)。方向案Bは、ゴシック体中心の現代的な可読性を保ちながら、ラベル・メモ的な実務装置で「今まさに整理してくれている」という安心感を出せるため、和風リスクを避けつつ、テック系・コンサル系にも寄りすぎないバランスを取りやすい。

## 14. フォント候補

K-SNAPSTEPは長い説明文・読みものが多いため、読みやすさを優先する。

| 案 | 内容 | 評価 |
|---|---|---|
| 案A | 見出しNoto Serif JP系、本文Noto Sans JP系 | 見出しに経験・落ち着きを残せるが、方向案Bの「現在進行形」のトーンとはやや相性が弱い |
| 案B | 見出し・本文ともにゴシック体、太さとサイズで階層を作る | 可読性が高く、方向案Bのゴシック中心の方針と一致する |
| 案C | システムフォントを中心にし、Webフォントの読み込みを最小限にする | 表示速度は最も有利だが、書体の個性は最小限になる |

**推奨**: 案B。方向案Bのトーンと一致し、長文の読みものページでも可読性を確保しやすい。太さ(ウェイト)の使い分けで階層を作ることを基本とする。

| 用途 | 方向 |
|---|---|
| ページタイトル | ゴシック体・太め |
| セクション見出し | ゴシック体・中太 |
| 本文 | ゴシック体・通常 |
| 補足 | ゴシック体・通常、やや小さめ、補助テキスト色 |
| 料金 | 数字を大きめ・太めに、単位(円・税込・/回・/月)は小さめ |
| 英数字 | 桁の揃う欧文フォント(等幅数字)を別途指定する方向 |
| 読みもの本文 | 本文と同じゴシック体、行間・文字サイズを長文向けにやや広めに |
| フォーム | 本文と同じゴシック体、入力欄はやや大きめのサイズで見やすく |
| コード・URL表記 | 等幅(モノスペース)フォント。K-SNAPSTEP側はコード例を扱うページがないため、URL表記程度の軽い用途にとどまる |

**表示速度への配慮**: 日本語Webフォントはファイルサイズが大きいため、新規に追加する場合は使用ウェイトを絞り、システムフォントとのフォールバックを用意する(`MARORIRI_DESIGN_GUIDE.md`10番と同じ方針)。最終確定はしない。

## 15. 余白とレイアウト

カードを並べて情報量を処理するのではなく、見出し・短い導入文・罫線・余白・背景色の切り替え・箇条書き・比較ブロック・料金バッジ・補足欄を中心にする。

| 項目 | 方針 |
|---|---|
| 本文の最大幅 | セクションの最大幅より狭く設定し、長文の可読性を優先する |
| セクションの最大幅 | 既存`.section-wrap`のようなトークン化された値を継続する方向(具体的な数値は次回) |
| 読みもの本文幅 | 本文の最大幅と同じ考え方だが、長文であることを踏まえてやや狭めに調整する余地を残す |
| ファーストビューの高さ | トップページのみやや高さを持たせ、下層ページは本文へすぐ入れる高さにする(`KSNAPSTEP_WIREFRAME.md`6番と同じ) |
| セクション間の余白 | 「大・中・小」の3段階で統一する |
| 2列を使う場面 | サービス比較(1日WEB担当者/月額サポート)、対応領域の役割分担、勉強会/個別相談のような「明確に対になる情報」 |
| 1列で読ませる場面 | 経歴、判断軸、読みもの本文など、地の文が中心のセクション |
| スマートフォンでの情報順 | テキスト(見出し→本文→CTA)を先に、図版・写真は後に |
| 長いページの区切り | 罫線・背景色の切り替えで区切り、実際に手順・時系列であるセクションにのみ番号を使う |

具体的なピクセル数は候補として次回示すが、固定しすぎない。

## 16. 見出し

| 階層 | 方向 |
|---|---|
| サイト名 | ヘッダー・フッターのロゴ領域(8・9番) |
| ページタイトル(H1) | 各ページ1つ、最も大きく |
| ファーストビューの主見出し | `KSNAPSTEP_SITE_SPEC.md`の確定コピーをそのまま使用 |
| セクション見出し(H2) | ページタイトルより明確に小さく |
| 小見出し(H3) | 本文との連続性を優先し、太さで区別 |
| 補足見出し(FAQの質問文・カード内ラベル等) | ゴシック体・太さで区別 |
| 記事見出し | 読みもの記事本文内はH2から使う(記事タイトルがH1のため) |

英字の装飾見出し(旧サイトにあった「― Three threads, one philosophy.」的な処理)は多用しない。短い英字ラベルを使う場合も、装飾目的ではなく、情報整理(例: セクションの分類ラベル)のためだけに限定する。

下線・短い罫線・番号・背景色の使い分け: 見出し自体への下線装飾は基本的に使わず、セクションの区切りは罫線・背景色の切り替えのみで表現する。番号は実際の手順(1日WEB担当者のSTEP等)にのみ使う。

| 読みもの一覧 | カード化せず、罫線区切りのリスト |
