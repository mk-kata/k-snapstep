## 1. デザインガイドの目的

MARORIRI(育成事業)のデザイン方向性と、共通UIルールを整理する。K-SNAPSTEPの暫定デザイン方向「外部Web担当者の実務ノート」との関連性を保ちつつ、MARORIRI固有の目的(コーディングを入口にWeb実務者を育てる)に合うよう、構造面のみ共通化し、見た目の印象は明確に分ける。

- 現場の仕事に近い

## 10. デザイン方向案A

**「現場の確認ノート」**

- 実案件で使う確認メモ・チェック欄を連想させる
- 白・薄いグレーを基調
- 罫線、番号、ラベルで情報を整理する
- コード例は実務資料として見せる(装飾ではなく確認材料として)
- ゴシック体中心
- 真面目で分かりやすい
- K-SNAPSTEPより少し軽く、学びの余白を持たせる
- 成長を一直線の工程にしない

---

## 11. デザイン方向案B

**「視野が広がるWeb実務」**

- コーディングからWeb全体へ視野が広がることを表現する
- 要素同士のつながりを線や配置で見せる
- コード・デザイン・CMS・確認・説明・進行が関連する構成
- 背景色の切り替えで視点が変わる印象を出す
- K-SNAPSTEPより少し柔らかく、動きがある
- スクール風のステップ表現は避ける
- 抽象図版を必要な箇所だけ使う

## 12. 2案の比較

| 観点 | 方向案A(現場の確認ノート) | 方向案B(視野が広がるWeb実務) |
|---|---|---|
| MARORIRIの目的との一致 | 高い(判断力育成・実務確認の印象と合う) | 非常に高い(「視野が広がる」というMARORIRIの中核概念を視覚的に体現できる) |
| K-SNAPSTEPとの差 | 中程度(罫線・ラベルによる整理はK-SNAPSTEPの方向案Bと手法が近く、差別化には色・テンポの工夫が別途必要) | 高い(背景色の切り替え、要素間のつながり線、抽象図版の使用で体験として明確に異なる) |
| 読みやすさ | 高い | 中〜高(つながりを見せる図版がテキスト読解の妨げにならないよう注意が必要) |
| 実案件感 | 高い | 中(視野拡大の表現に寄りすぎると抽象的・コンセプチュアルになる恐れがある) |
| スクールに見える危険性 | 低い | 低い(ただし抽象図版の使い方次第でコンサル会社・デザイン会社的に見えるリスクがある) |
| 実装負担 | 低〜中(構造がシンプル) | 中〜高(つながり線・背景切り替え・図版が増える分コストが上がる) |
| スマートフォンでの見せやすさ | 高い | 中(横方向のつながり表現を縦積みへ変換する工夫が必要) |

## 13. 推奨する方向

**方向案Bを推奨する。**

理由: MARORIRIの中心的な考え方「コーディングを入口に、Webの現場を見渡せる人へ。」を最も直接的に体現できるのは、視野の広がりを構造(背景の切り替え・要素のつながり)で見せる方向案Bである。K-SNAPSTEPとの視覚的な差別化も明確に取りやすい。

ただし、12番のとおり方向案Bは実案件感がやや弱まるリスクがあるため、方向案Aの「確認メモ・判断ポイントのラベル表示」という手法を、B全体の構造の中に部分的に組み込むハイブリッド運用を推奨する(例: 視野が広がる大きな構成の中に、判断ポイントごとの小さな確認ラベルを配置する)。両案は対立する選択肢ではなく、Bを骨格、Aの一部手法を装置として使う関係として扱う。

## 15. フォント候補

| 案 | 内容 | 評価 |
|---|---|---|
| 案A | 見出し・本文ともにゴシック体、ウェイトとサイズで階層化、コードのみ等幅 | 実装・保守が容易だが、K-SNAPSTEPとの差別化が弱くなりやすい |
| 案B | 見出しに少し個性のあるゴシック体、本文は可読性の高い標準ゴシック、コードは等幅 | 「学びの伸びしろ」を見出しの個性で表現しつつ、長文の可読性も確保できる |
| 案C | システムフォント中心、読み込み速度優先、コードのみ等幅 | 表示速度は最も有利だが、ブランドの個性を出しにくい |

**推奨**: 案B。MARORIRIは「現場に近いが、学びの場でもある」という二面性を持つため、見出しにだけ個性のあるゴシックを使うことで、K-SNAPSTEPの実務一辺倒のトーンとの違いを出しつつ、本文・記事は標準ゴシックで読みやすさを優先する。

| 用途 | 方向 |
|---|---|
| サイト名 | 見出し用フォント(個性のあるゴシック) |
| ページタイトル | 見出し用フォント・太め |
| セクション見出し | 見出し用フォント・中太 |
| 本文 | 標準ゴシック・通常 |
| 補足 | 標準ゴシック・やや小さめ、補助テキスト色 |
| 料金 | 数字を大きめ・太めに、単位は小さめ(K-SNAPSTEPと同じ考え方) |
| コード例 | 等幅フォント |
| ファイル名 | 等幅フォント・小さめ |
| ラベル | 標準ゴシック・太め、小さめサイズ |
| 読みもの本文 | 標準ゴシック、行間・文字サイズを長文向けに調整 |
| フォーム | 標準ゴシック、入力欄はやや大きめ |

**K-SNAPSTEPと同じフォントを使う場合**: 実装・保守が容易で、トークン共有がしやすい。ただし見出しの個性を出しにくく、2サイトが同じテンプレートに見えるリスクが増す。
**変える場合**: ブランドの差別化が明確になる。ただしフォント読み込みが増え、パフォーマンスに影響する。本文用フォントは共通化し、見出し用フォントのみ分ける折衷案も検討に値する。

## 16. ページのテンポ

K-SNAPSTEPは状況を落ち着いて整理する実務ノート的な構成だが、MARORIRIは同じ余白ルールを基礎にしつつ、次の違いを持たせる。

- 質問や状況から始まる
- 具体例を見せる
- 判断の過程を見せる
- 複数の視点がつながる
- 読み進めると視野が広がる
- 長い文章だけで終わらない(ただし短いカードを大量に並べない)

| 見せ方 | 使用場面 |
|---|---|
| 状況→確認→判断の3段構成 | 「学ぶこと・目指す姿」の各力の説明、記事本文 |
| 修正前→確認点→修正後 | コード例を扱う記事・具体例 |
| 指示→不明点→質問内容 | 「確認して伝える」の力を説明する具体例 |
| コード→判断理由→次回確認すること | コーディングチェックの具体例 |
| コーダーの担当範囲→他担当者へ相談する範囲 | 「Web全体を見る」の力、案件全体相談の説明 |

## 20. コード表示

- コードブロック背景: 14番のカラーセットで定義したダーク背景(セット2推奨時は`#241F2C`)を使い、サイト全体は白・薄いグレー基調のまま、コードブロックのみ暗い区画として独立させる(サイト全体を黒背景にはしない)
- 文字色: 背景に対して十分なコントラストを持つ明るい色(セット2推奨時は`#DAD5E0`系)
- 等幅フォント: コード専用に指定(15番)
- 言語名: コードブロック上部にラベル表示
- ファイル名: 言語名と併記、または代わりに表示
- 横スクロール: 長い行は折り返さず横スクロールとし、スクロール可能であることが分かる表示にする
- 行番号: 長いコード例のみ表示、短い例では省略可
- コピー機能: コードブロック右上に小さなアイコンボタン(18番)
- 強調行: 背景色をわずかに変えて特定行を目立たせる
- 修正前・修正後: 2つのコードブロックを並べる、またはタブ切り替えで比較する
- 差分表示: 追加行・削除行を色分けするが、緑は使わずアクセント系の色+記号(+/-)で区別する
- コードの下に判断理由を置く方法: コードブロックの直下に「判断理由」ラベル付きの短いテキストブロックを配置し、コードと理由をセットで読ませる(16番「コード→判断理由→次回確認すること」と連動)

コード画面そのものを装飾として使わず、説明のためにのみ使用する。

## 29. アクセシビリティ

- 文字と背景のコントラストを、読みやすい水準で確保する
- アクセント色だけで違いを示さない(エラー・差分表示等はアイコン・記号・文言も併用)
- 本文サイズを小さくしすぎない
- 行間を十分に確保する(記事本文・コード解説部分)
- リンクとボタンを、色だけでなく形状でも見分けられるようにする
- キーボード操作時のフォーカス表示をデザイン段階から前提にする(14番のフォーカス色)
- フォームエラーを色だけで示さない
- 必須・任意をラベル+テキストで明示する
- 見出し階層を装飾都合で崩さない
- コードブロックの横スクロールが、キーボード操作でも可能であることを確認する
- コピー機能の操作結果(コピー完了)を、視覚だけでなく支援技術にも伝わる形で示す
- アコーディオンはキーボード操作でも開閉できるようにする
- 動きを減らす設定(prefers-reduced-motion等)に配慮する
- 画像の代替テキストを設定する
- 画像内に重要な文章を閉じ込めない
