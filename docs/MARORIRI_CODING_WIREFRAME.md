## 11. マロリリコーダー部(中心サービスページ)

`MARORIRI_CODING_SPEC.md`10〜13番の内容を統合し、既存確定本文(`MARORIRI_SITE_SPEC.md`15-4、全12セクション)から再利用できる部分を取り込む。

### ファーストビュー
```text
┌──────────────────────────┐
│ マロリリコーダー部                          │
│ コーダー・Web制作者向け                       │
│ 月額3,300円(税込) ／ 月1回のオンライン勉強会      │
│ ／ 月1回・60分の個別相談                     │
│ コードだけでなく、現場での判断を扱います           │
│ [参加・相談について問い合わせる]                 │
└──────────────────────────┘
```
「初心者向けスクール」「動画教材」「会員制コミュニティ」を想起させる演出(進捗バー・修了証・レベルバッジ等)は使わない(`MARORIRI_SUBPAGE_WIREFRAME.md`16番の方針を継承)。

### 対象者
実案件で困っている状態として見せる(単なる学習者の悩みにしない)。
```text
- 指示の意味を判断できない
- AIのコードが正しいか分からない
- デザインの意図を読み取れない
- クライアントへ何を確認すればよいか分からない
- 自分の担当範囲を決められない
- コーディング以外の質問に対応できない
```
装飾カードを大量に並べず、チェックリストまたは短い状況別ブロック。

### 月1回のオンライン勉強会
固定カリキュラムではないことを明記。扱う内容例(HTML・CSSの考え方／デザインの読み取り／AIコードの確認／実案件の進め方／クライアントへの確認／ケアレスミスの防止／CMSや周辺領域)を、その月のテーマとして扱う旨を添える。

### 月1回・60分の個別相談
```text
┌─ 勉強会 ─────────┐  ┌─ 個別相談 ─────────┐
│ 複数人で考え方や事例を共有  │  │ 本人の状況や仕事について確認 │
└─────────────────┘  └───────────────────┘
```
完全に固定された役割分担ではなく、状況に応じて扱う内容が変わることも明記する。

### コーディングチェック
月額サービスの内容とは区切り線で明確に分ける。
```text
── 実案件で必要になった場合 ──

コーディングチェック          1案件 5,000円(税込)
  全ページ対象・再チェック回数は限定しない・修正代行ではない
  なぜ修正が必要か、次回から何を確認すればよいかを伝える
```
追加購入を促す大きな料金カードにはしない。

### 案件全体相談
```text
案件全体相談                1案件 10,000円(税込)・オンライン60分
  仕様の読み取り・作業範囲・進め方・クライアントへの確認
  役割分担・納期や工数・対応できること/できないこと
```
コーディングチェック(実装されたコードを確認)との違いを明記(案件全体相談は着手前・進行中の案件全体を確認)。上下関係・上位プランには見せない。

### 追加個別相談
```text
案件以外の追加個別相談        60分 5,000円(税込)
  月額内の個別相談とは別に、追加で相談したい場合の選択肢
```
独立した大きなサービスカードにせず、料金・利用方法の補足として配置。

### 具体例
既存確定本文にある具体例・「判断するときの視点」(`MARORIRI_SITE_SPEC.md`15-4セクション4〜6)を活かし、企業向けページと同じカードデザインは使わず、「状況→どこに迷うか→何を確認するか→どう判断するか」という検討過程が見える構成にする。

### ページ内ナビ(候補)
マロリリコーダー部について／勉強会／個別相談／コーディングチェック／案件全体相談／料金／FAQ

### FAQ
質問数が多いためアコーディオン形式を推奨案とする。実装(JavaScript)はまだ行わない。

## 12. 学ぶこと・目指す姿

カリキュラム・修了課程には見せない。5段階(正しく作る／コードを判断する／確認して伝える／Web全体を見る／仕事を進める)を、互いに関係する力として設計する(`MARORIRI_CODING_SPEC.md`18番)。

各段階について次を記載する。
- 何ができる状態か
- 現場でどのように使うか
- どこまでを目指すか

### Web全体を見る(4段階目)の扱い
CMS・サーバー・ドメイン・メール・フォーム・SEO・アクセス解析・更新運用・制作進行を、すべて専門家として習得する意味ではないと明記する。目指すのは「状況を確認し、誰へ相談するか判断できる状態」。

### ページ末尾
マロリリコーダー部への導線を主とする。問い合わせを同じ強さで並べず、まずサービス内容を確認してもらう流れにする。

## 15. 記事詳細

- コードだけでなく、判断理由を本文で説明する(コード例は判断の根拠を示す補助とし、コードのみで完結させない)

## 21. スマートフォン共通ルール

- すべて1カラムに変換する
- 5つの力(トップ セクション4)は縦のグループとして表示し、固定の修了課程のような番号強調はしない
- 勉強会/個別相談の2列対比は縦に積む
- コーディングチェック・案件全体相談・追加個別相談の区切り線構成はそのまま維持(横→縦の変換は不要、元々縦並び)
- コードブロックは横スクロールを許容し、無理に折り返さない
- ページ内ナビ(マロリリコーダー部)は開閉式にして上部を圧迫しない
