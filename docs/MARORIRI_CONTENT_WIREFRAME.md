# MARORIRI 読みもの ワイヤーフレーム設計

`docs/MARORIRI_SITE_SPEC.md`(確定仕様・19番)、`docs/MARORIRI_WIREFRAME.md`(共通レイアウト)、`docs/MARORIRI_SUBPAGE_WIREFRAME.md`(下層6ページ)の内容と矛盾しないよう作成しています。記事データ・URL・分類方法はいずれも今回の設計案であり、最終決定ではありません。note記事の取得・選定・移行、デザイン、Astro実装は行っていません。

---

## 1. 読みものワイヤーフレームの目的

固定7ページ・下層6ページのワイヤーフレームに続き、「読みもの」関連の4ページ種別を設計する。

1. 読みもの一覧ページ
2. 「頭の中をほどく」シリーズ一覧ページ
3. 「小さな会社のホームページ見直しノート」シリーズ一覧ページ
4. 記事詳細ページ

読みものは、単なる集客用ブログではなく、MARORIRIの考え方や判断方法を伝える役割を持つ(仕様書19番)。そのため、記事一覧・詳細のどちらも、サービスへの誘導が強すぎない設計を基本方針とする。

## 2. 読みもの全体の構造

```
読みもの一覧
├── 「頭の中をほどく」シリーズ一覧
│     └── 記事詳細
└── 「小さな会社のホームページ見直しノート」シリーズ一覧
      └── 記事詳細
```

グローバルナビの「読みもの」(仕様書4番、通常ナビ6項目のうちの1つ)は、読みもの一覧ページへリンクする。2シリーズに上下関係はなく、一覧ページ上でも対等に扱う。

## 3. 読みもの一覧ページ

### ページの役割
2シリーズの違いを最初に伝え、読みたい内容からシリーズまたは記事を選べるページにする。

### ファーストビュー
大きな画像や強いサービスCTAは置かない。パンくず(トップ＞読みもの)→ページ名「読みもの」→見出し(今後作成)→短い導入文→2シリーズの違いの要約、という順で簡潔に構成する。

```text
┌─────────────────────────────┐
│ トップ ＞ 読みもの                       │
│ 読みもの                               │
│ 見出し(今後作成)                        │
│ 導入文(1〜2文、今後作成)                  │
└─────────────────────────────┘
```

### 2シリーズの紹介

**比較**

| 案 | 特徴 |
|---|---|
| 左右2列 | 「対等な2つの選択肢」であることが一目で伝わり、比較しやすい。説明文の長さが揃わないと高さがアンバランスになりやすい。 |
| 上下2ブロック | 各シリーズの説明を余裕をもって書ける。スマートフォンと同じ並びで実装がシンプル。ただし2つ目がスクロールしないと見えない。 |

**推奨**: 左右2列(デスクトップ)。2シリーズに上下関係がないことを一目で示せるため。説明文は同程度の文字数に揃える方針とし、次回のコピー作成時に反映する。

```text
┌───────────────────┐  ┌───────────────────────────┐
│ 頭の中をほどく             │  │ 小さな会社のホームページ見直しノート        │
│ 仕事・人間関係・判断できない…   │  │ Webサイト・制作会社・CMS・発注・更新・運用… │
│ [シリーズを見る]            │  │ [シリーズを見る]                      │
└───────────────────┘  └───────────────────────────┘
```

### 最新記事

**比較**

| 案 | 特徴 |
|---|---|
| 全記事を時系列で表示 | シンプルで新しい記事がすぐ分かるが、2シリーズが混ざりシリーズの違いが薄れる。 |
| シリーズごとに最新記事を表示 | 2シリーズの個性を保ちながら新着も見せられる。記事が少ない段階では件数が少なくなる。 |
| 最初にシリーズを選んでもらう(記事を出さない) | 導線はシンプルだが、一覧ページに来た価値(記事の中身を覗ける)が薄い。 |

**推奨**: シリーズごとに最新記事を表示する(各シリーズ最大3件程度、あれば表示)。2シリーズ紹介ブロックの下に、シリーズごとの最新記事を並べる。記事数が少ない時期でも、件数を決め打ちにせず「あるものだけ」表示すれば不自然にならない。

```text
┌───────────────────┐  ┌───────────────────────────┐
│ 頭の中をほどく             │  │ 小さな会社のホームページ見直しノート        │
│ (シリーズ紹介)              │  │ (シリーズ紹介)                       │
│ ・最新記事タイトル             │  │ ・最新記事タイトル                     │
│ ・最新記事タイトル             │  │ ・最新記事タイトル                     │
│ [シリーズをすべて見る]         │  │ [シリーズをすべて見る]                 │
└───────────────────┘  └───────────────────────────┘
```

### 記事カードに表示する情報

| 項目 | 一覧ページでの扱い |
|---|---|
| シリーズ名 | 表示(どちらのシリーズか一目で分かるラベルとして) |
| 記事タイトル | 表示(必須) |
| 概要文 | 表示 |
| 公開日 | 表示 |
| 更新日 | 非表示(一覧では不要、詳細ページのみ) |
| サムネイル画像 | 任意(あれば小さく表示。文章を読ませるシリーズのため、大きく扱わない。画像がない記事でも崩れない設計とする) |
| 読了時間 | 非表示(推測値になり不正確になりやすいため今回は採用しない) |
| カテゴリー | 非表示(一覧ページでは扱わない。各シリーズ一覧ページ側で検討) |
| タグ | 非表示(同上) |

**推奨最小構成**: シリーズ名(ラベル)+記事タイトル+概要文+公開日。サムネイルは任意項目とする。

### サービスへの導線

ページ末尾に、強い問い合わせCTAは置かない。「MARORIRIについて」「1日WEB担当者」「対応できること」への、テキストリンク程度の控えめな導線とする。

```text
関連ページ: MARORIRIについて ／ 1日WEB担当者 ／ 対応できること
```

## 4. 「頭の中をほどく」シリーズ一覧

### ページの役割
このシリーズの考え方を短く伝え、記事を探せるページにする。

### ファーストビュー
シリーズ名・シリーズの説明・読みもの一覧へ戻る導線・パンくずを、抽象的なビジュアルに頼らず、文章中心で構成する。

```text
┌─────────────────────────┐
│ トップ ＞ 読みもの ＞ 頭の中をほどく          │
│ 頭の中をほどく                        │
│ シリーズの説明(2〜3文)                  │
│ [読みもの一覧へ戻る]                    │
└─────────────────────────┘
```

### 記事の分類

想定テーマ(仕事・Web運用／人間関係／思考整理)をカテゴリーとして固定するかは未確定。

**比較**

| 案 | 特徴 |
|---|---|
| カテゴリーで分ける | 整理されて見やすいが、記事数が少ない段階ではカテゴリーごとに1記事ずつとなり、かえって分断されて見える。 |
| タグで探す | 柔軟に複数テーマを跨げるが、タグ一覧UIが必要で、記事が少ない段階ではタグクラウード自体が寂しい。 |
| すべて時系列で並べる | 実装・運用が最もシンプルで、記事が少ない段階に向く。記事が増えると探しにくくなる。 |
| シリーズ内でテーマ別の見出しを置く | カテゴリーページを新設せずに緩やかに区分できるが、見出し下に記事が0件の期間が生じうる。 |

**推奨**: 公開初期は時系列表示を基本とし、記事が一定数増えた段階でテーマ別の見出し表示へ移行する、という2段階の方針とする。カテゴリーページ自体は今回作り込まない。

### 記事一覧
サムネイル画像を大きく扱わず、タイトル・概要文・公開日を中心とした構成にする(3番の記事カード方針と同じ最小構成)。

```text
記事タイトル1
概要文 ／ 公開日
──────────────
記事タイトル2
概要文 ／ 公開日
```

## 5. 「小さな会社のホームページ見直しノート」シリーズ一覧

### ページの役割
小さな会社や事業者が、自社のWebサイトや制作体制について考えるための記事を探せるページにする。

### ファーストビュー
シリーズ名・シリーズの説明・対象者・読みもの一覧へ戻る導線・パンくずを配置する。手順書やスクリーンショット中心の「ホームページの作り方を教える技術ブログ」には見せず、MARORIRIサイト全体と同じ「判断・整理」の語り口を保つ。

```text
┌─────────────────────────────┐
│ トップ ＞ 読みもの ＞ 小さな会社のホームページ見直しノート │
│ 小さな会社のホームページ見直しノート               │
│ シリーズの説明(2〜3文)＋対象者の一文               │
│ [読みもの一覧へ戻る]                          │
└─────────────────────────────┘
```

### 記事の分類
想定テーマ例(ホームページの見直し／制作会社とのやり取り／CMS・更新／サーバー・ドメイン／SEO・アクセス解析／Web担当者がいない会社の判断)は、公開時からカテゴリーとして固定しない。4番と同じく、記事数が少ない時期は時系列、増えた段階で分類を追加できる設計とする。

### サービスとの関係
1日WEB担当者・月額Web担当サポートに関係する内容が多いが、記事一覧全体を営業ページのようには見せない。シリーズ説明文の末尾、またはページ末尾に、控えめな1行のサービス導線を置く案とする。

```text
（シリーズ説明の末尾、または末尾）
関連するサービス: 1日WEB担当者 ／ 月額Web担当サポート
```

## 7. 記事カードの共通ルール

読みもの一覧・シリーズ一覧の両方で、記事カードは次で統一する。

- シリーズ名(ラベル)+記事タイトル+概要文+公開日を基本構成とする。
- サムネイルは任意。使う場合も小さく、文章より目立たせない。
- 丸みの強い装飾カードにせず、罫線または余白のみで区切る(サイト全体の方針を踏襲)。
- 更新日・読了時間・カテゴリー・タグは、一覧のカードには表示しない。

---

## 8. 記事本文の共通ルール

| 項目 | 方針 |
|---|---|
| 本文幅 | 共通レイアウトルール(下層ページ6番)の「読みやすい幅」を踏襲し、サイト内で最も長文になる記事本文で特に重視する |
| 見出し階層 | 記事タイトルがH1のため、本文中の見出しはH2から使う |
| 段落間の余白 | 通常の「中」余白を基本とする |
| 引用表示 | 左に縦罫線+インデントのシンプルな引用ブロック |
| 箇条書き | 通常のリストマーカーのみ。装飾を加えない |
| 補足ボックス | 背景色を変えた枠を、まとめ・注記など限定的な用途にのみ使う(多用しない) |
| 画像とキャプション | 画像下に小さいキャプション欄を用意(任意) |
| 外部リンク | 視覚的に区別(下線+色)する方針のみ決め、新規タブか同一タブかは次回判断 |
| noteから移行した記事である旨の表示 | 記事ごとに任意で設定できるようにする(下記) |

**noteからの移行表示について**: 「note版はこちら」のようなクレジットリンクを記事末尾に置くかどうかは、note側の記事を残すかどうかの方針(19番参照)と連動するため、記事データ項目(`originalNoteUrl`)を任意項目として持たせ、記事ごとに表示・非表示を切り替えられる設計とする。

## 9. サービス導線の方針

記事の内容に関係する場合だけ、記事末尾に控えめなリンクを置く。全記事に同じ大型CTAを機械的に置かない。

| 記事のテーマ例 | 導線の例 |
|---|---|
| Webサイトに関する内容 | 1日WEB担当者、または対応できること |
| 思考整理に関する内容 | プロフィール、またはMARORIRIについて |
| コーディングに関する内容 | マロリリコーダー部 |

「頭の中をほどく」シリーズの記事すべてをサービスへ強く誘導することはしない。記事データ項目(`serviceLink`・`serviceLinkText`)を任意項目として持たせ、関係がある記事のみ設定する運用とする。

```text
（本文末尾、あれば表示。なければ非表示)
この内容に関連するページ: [1日WEB担当者を見る]
```

## 10. 関連記事・前後記事の方針

### 関連記事
優先順位: (1)同じシリーズ → (2)近いテーマ → (3)新しい記事。自動判定にするか手動設定(記事データの`relatedArticles`)にするかは、今回決定しない。

### 前後記事

| 案 | 特徴 |
|---|---|
| 日付順(サイト全体) | 実装は単純だが、シリーズを跨いで無関係な話題に飛ぶ可能性がある |
| シリーズ内の日付順 | シリーズという文脈を保ったまま読み進められる |
| 手動指定 | 意図した順番で読ませられるが、記事が増えると運用の手間が大きい |

**推奨**: シリーズ内の日付順。ただし最終決定はしない。

## 11. URL構造の比較

| 案 | 例 | 特徴 |
|---|---|---|
| A: `/journal/` | `/journal/untangle/article-slug/` | 「雑誌」的な響きがあるが、`untangle`(頭の中をほどく)等の英訳スラッグはURLだけでは日本語ユーザーに推測しづらい |
| B: `/articles/` | `/articles/thinking/article-slug/` | 「記事である」ことは明確で短いが、`thinking`のようなカテゴリ語はシリーズの実際のニュアンスを大まかにしか表さない |
| C: `/reading/` | `/reading/untangle/article-slug/` | 「読みもの」という日本語ページ名との対応が取りやすいが、英訳スラッグの分かりにくさはAと同様 |

**推奨**: 案Cをベースにする。「読みもの」という日本語ページ名(ナビ表記・パンくず表記)とURLの語感が対応しやすく、サイト内の一貫性を保ちやすいため。ただし`untangle`等の英語スラッグ自体が適切かどうかは今回決定せず、シリーズ名の英訳(またはローマ字表記)を含め、URL確定時にあらためて検討する。

URLの階層(`/reading/`一覧 → `/reading/[series]/`シリーズ → `/reading/[series]/[slug]/`記事)は、シリーズの所属が一目で分かるため、3案とも共通して採用する方向で問題ない。

## 14. スマートフォン配置

- 読みもの一覧の左右2列(シリーズ紹介)は、縦に1列で積む。

## 15. note移行時に確認すること

- 元記事にあるカテゴリ・タグと、MARORIRIサイトの分類方針(4・5番)との対応関係
- 画像の再アップロード方法(noteの画像URLをそのまま参照しない前提で、サイト内に取り込む方法)
- 記事本文中の内部リンク・外部リンクが、移行後も正しく機能するかの確認
- note記事内で言及されている過去のブランド表現・サービス名が、MARORIRIの現行の名称・料金と矛盾していないかの確認
- 移行後、noteの元記事をどう扱うか(19番「note側の記事を残すか」と連動)
