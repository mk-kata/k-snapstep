## 3. 共通ヘッダー

| 項目 | 内容 |
|---|---|
| ロゴの位置 | 左上。クリックでトップページへ。 |
| グローバルナビの位置 | デスクトップ: ロゴの右側、ヘッダー内で横並び。スマートフォン: 非表示にし、ハンバーガーメニューに格納。 |
| お問い合わせCTAの扱い | ナビ内の他項目と同列のテキストリンクにせず、ボタンとして視覚的に独立させる(お問い合わせがサイト最重要の導線のため)。 |
| スマートフォンのメニュー形式 | ハンバーガーアイコン→ドロワー(画面端からスライドして表示)を推奨。フルスクリーンオーバーレイは、通常ナビ6項目+お問い合わせ程度であれば必須ではないが、ドロワー内の項目数が増えた場合の代替として検討可。 |

**スクロール時に固定するか(推奨案)**

| 観点 | 固定(sticky)ヘッダー | 固定しないヘッダー |
|---|---|---|
| 利点 | 長文の詳細ページ(1日WEB担当者、月額サポート等)を読み進めても、いつでも他ページやお問い合わせへ移動できる。 | コンテンツを覆わず、特にスマートフォンで縦の表示領域を最大限使える。 |
| 注意点 | 高さがあると、スマートフォンの限られた画面でコンテンツを圧迫する。 | 長いページの途中で、ナビやお問い合わせへ戻るには一度スクロールを戻す必要がある。 |

**推奨**: 固定ヘッダーを採用するが、高さを抑えたコンパクトな形にする。デスクトップはロゴ・ナビ・お問い合わせボタンを1段に収め、スマートフォンはロゴとハンバーガーのみの最小構成にして、コンテンツの圧迫を避ける。この判断は次回、実際のページ分量を見ながら再確認してもよい(12番参照)。

## 4. グローバルナビゲーション

**確定構成**(仕様書4番と一致): 通常ナビ6項目+独立したお問い合わせCTA。合計7つの主要導線となるが、「7項目の横並びナビ」ではない。

```
[通常ナビ6項目]
1. 1日WEB担当者
2. 月額Web担当サポート
3. 対応できること
4. 読みもの
5. 片山まゆみについて
6. コーダーの方へ

[独立したCTAボタン]
お問い合わせ
```

「コーダーの方へ」のリンク先ページ名は「マロリリコーダー部」(仕様書4番の確定表記を踏襲)。

**「サービスの種類が多く見えすぎない」ための整理**

通常ナビ6項目をすべて同じ強さで横並びにすると、サービスメニューが多すぎる印象になりやすい。ドロップダウンで隠す案は、単発(1日WEB担当者)と継続(月額Web担当サポート)を同列に見せるという仕様書4番の考え方と矛盾するため採用しない。代わりに、項目間の余白(スペーシング)だけで緩やかにグループ分けする。

```
[1日WEB担当者] [月額Web担当サポート] [対応できること]   [読みもの] [片山まゆみについて] [コーダーの方へ]   (お問い合わせボタン)
└──────── サービスの核 ────────┘   └──────── 会社・活動の情報 ────────┘
```

- 左側3項目: サービスの核(単発・継続・対応範囲)
- 中央3項目(通常ナビの4〜6番目): 会社・発信の情報
- お問い合わせ: 通常ナビとは別の独立したボタン

通常ナビ6項目はいずれも1クリックで到達でき、階層で隠さない。お問い合わせはボタンとして視覚的に切り分ける。

**デスクトップ表示**: 通常ナビ6項目を1段の横並びにし、お問い合わせボタンを右端に独立配置する。項目数が多いため、通常ナビの文字サイズはやや小さめにし、余白でグループの区切りを示す。

**スマートフォン表示**: ハンバーガーメニュー内に、通常ナビ6項目とお問い合わせへの導線を表示する。デスクトップと同じ2グループの構成を、ドロワー内でも罫線または余白で再現する。お問い合わせは、メニュー内でも他の項目と視覚的に区別する(具体的なボタンデザイン・配色はデザイン段階で決定)。

## 6. 共通レイアウトのルール

| 項目 | 方針 |
|---|---|
| コンテンツの最大幅 | サイト全体で1種類の最大幅を基本とし、写真や図版など「幅いっぱいに見せたい要素」だけ例外的に広げる、という2段階の考え方にする(具体的なピクセル数は次回)。 |
| 本文の読みやすい幅 | 見出しや装飾要素より本文(段落テキスト)の行あたり文字数を狭く保つ。1日WEB担当者・月額サポートなど長文の詳細ページで特に重視する。 |
| セクション間の余白 | 「大(セクションとセクションの間)」「中(セクション内の要素間)」「小(要素内の行間・項目間)」の3段階で統一し、ページごとにばらつかせない。 |
| 見出し階層 | ページタイトルを1つ、各セクション見出しを1段下、セクション内の小見出し(パターン名など)をさらに1段下、の3階層を基本にする。 |
| CTAの基本配置 | 各ページ共通で、(1)ファーストビュー内、(2)ページ末尾の合計2箇所を基本とする。ページが長い場合のみ、中間に1箇所補助CTAを置く(1日WEB担当者・月額サポート等、既存本文でアンカー誘導が想定されている箇所に対応)。 |
| 料金・比較表の表示方法 | 2項目の比較(1日WEB担当者/月額サポートなど)はカード形式、複数項目の一覧(コーダー部の料金メニュー等)は表形式、と使い分ける。 |
| 長いページの区切り方 | 罫線や背景色の切り替えで区切り、通し番号(01/02…)は「実際に手順・時系列であるセクション」にのみ使う。単なる情報の切れ目に番号を振らない。 |

## 8. 各セクションのデスクトップ配置

### セクション1｜ファーストビュー

**方針**: MARORIRIは制作会社ではなく、発注側の判断を整理するサービスである。この違いを、華美な演出ではなく「状況を整理する」という行為そのものを想起させる、控えめな抽象図版で示す。人物写真やにぎやかなイラストは避ける(人物写真はプロフィールページで使う要素、水彩調の柔らかいイラストは旧サイトの方向性であり今回は採用しない)。

- 見出し・本文は左寄せのテキストブロックとして配置し、右側(または下側)に図版を置く、左右2分割のレイアウトを推奨する。中央寄せの派手なマーケティング型ヒーローにはしない。
- 主CTA「今の状況を相談する」・副CTA「1日WEB担当者を見る」は本文の直下に横並びで配置し、主CTAを視覚的に強くする。
- **料金はファーストビューに出さない**。ファーストビューの役割は「何をするサービスか」を伝えることであり、料金の比較(1日WEB担当者/月額サポートどちらも55,000円)はセクション4で文脈とともに提示する方が誤解を招きにくい。
- 図版案: 「散らばった情報が整理されていく」ことを示す簡易な図解調のイラスト(具体的な素材は未定、12番参照)。

```text
┌─────────────────────────────────────────┐
│  見出し:「Webの判断を、社内だけで抱えないために。」│
│  本文(3〜4行)                              │
│  [今の状況を相談する] [1日WEB担当者を見る]     │        図版
│                                           │      (整理を示す抽象図)
└─────────────────────────────────────────┘
```

**スマートフォン**: テキスト(見出し→本文→CTA)を先に、図版はその下に配置。

### セクション2｜このような状態になっていませんか

**比較**

| 案 | 特徴 |
|---|---|
| 6枚カードを1列 | 縦に長くなりすぎる |
| 2〜3列グリッド | 一覧性は高いが、装飾的なカードにすると軽い内容に見えかねない |
| チェックリスト形式 | 「自分に当てはまるか」を確認する行為と相性がよい |
| 困りごとのグループ化 | 6項目を無理に統合する必要が生じ、確定本文と食い違うおそれ |

**推奨**: チェックリスト形式を、デスクトップでは2列に分けて配置する。丸みの強いカードや影の装飾は使わず、チェックマークのアイコン+短文+罫線区切りにとどめる。

```text
┌───────────────────────────────┐
│ 見出し:「このような状態になっていませんか。」  │
│ ✓ 項目1        ✓ 項目4         │
│ ✓ 項目2        ✓ 項目5         │
│ ✓ 項目3        ✓ 項目6         │
└───────────────────────────────┘
```

**スマートフォン**: 1列で6項目を縦に並べる。

### セクション3｜MARORIRIが行うこと

**検討**: 6つの行動(確認する/分ける/確認する/分ける/整理する/決める)を「1→6の直線工程」として番号付きで見せると、あたかも毎回同じ手順を機械的にこなすサービスに見えてしまう。実際は状況に応じて行き来する判断であるため、次を推奨する。

**推奨**: 番号を振らない2×3のゆるいグリッド配置とし、要素間を矢印でつながず、全体を緩やかな囲み(1つの枠)の中に収める。「これらすべてを状況に応じて行う」という関係性を、直線的な矢印ではなく、ひとまとまりの集合として見せる。

```text
┌─────────────────────────────────────┐
│ 見出し:「状況を確認し、次にすることを整理します。」│
│ ┌───────────────────────────┐       │
│ │ 現状確認   問題を分ける   情報確認   │       │
│ │ 今/今しない  担当整理    次を決める  │       │
│ └───────────────────────────┘       │
└─────────────────────────────────────┘
```

**スマートフォン**: 1列で6項目を並べるが、囲み枠は維持し、番号や矢印は付けない。

### セクション4｜単発と継続、2つの関わり方

**方針**: 1日WEB担当者を左・先に、月額Web担当サポートを右・後に配置し、1日WEB担当者のカードをわずかに大きく(または枠線を太く)して視覚的な優先度を示す。ただし上位・下位のラベルや「おすすめ」バッジは付けない。

**同額表記が不自然に見えない工夫**: 金額の直下に付ける単位表記を変える。

- 1日WEB担当者:「55,000円(税込) / 1回」
- 月額Web担当サポート:「55,000円(税込) / 月」

単位が異なることで、同じ数字でも性質の違いが視覚的にも伝わる。2枚のカードの間に「または」程度の軽い区切りを置き、「vs」のような対決を示す表現は使わない。カード下に、確定本文にある「上位・下位の関係ではない」という一文を、2枚に共通するキャプションとして配置する。

```text
┌─────────────────────┐  ┌───────────────────┐
│ 1日WEB担当者(やや強調)  │  │ 月額Web担当サポート    │
│ 一つの課題を集中整理    │  │ 月2回、継続的に確認     │
│ 55,000円(税込) / 1回  │or│ 55,000円(税込) / 月   │
│ [1日WEB担当者を見る]   │  │ [月額サポートを見る]    │
└─────────────────────┘  └───────────────────┘
   ※ どちらも上位・下位の関係ではありません
```

**スマートフォン**: 1日WEB担当者のカードを上に、月額Web担当サポートを下に縦積み。

### セクション6｜幅広い範囲を確認できる理由

**方針**: WordPress・GA4等のロゴを並べる「導入実績風」の見せ方は避ける。プロフィールページとは異なり、経歴のストーリーではなく「領域の広さ」を示すため、Web・CMS・EC・サーバー・SEO・解析といった領域が緩やかに重なり合う、抽象的な図(円や四角の重なり程度)を本文の脇に添える案を推奨する。ツールロゴの羅列は行わない。

```text
┌─────────────────────────────────┐
│ 見出し:「Webサイトだけでなく、その周辺まで確認します。」│
│ 本文(2段落)                    領域が重なる抽象図 │
│ 代表例(WordPress/MT/EC環境/サーバー/GA4)      │
│ [対応できることを見る]                      │
└─────────────────────────────────┘
```

**スマートフォン**: 本文を先に、図はその下(小さめ)に配置、または省略も可(次回判断)。

### セクション7｜必要に応じて、実作業にも対応します

**方針**: セクション6より明確に小さく、背景色を切り替えるなどして「補足」であることを視覚化する。CTAは「対応できることを見る」のみとし、単独で目立つボタンサイズにはしない(テキストリンク寄りの控えめな見せ方)。

```text
┌───────────────────────────┐
│ 見出し:「必要に応じて、実作業にも対応します。」  │
│ 本文(短め)                          │
│ 対応できることを見る →               │
└───────────────────────────┘  (背景色を他セクションと変える程度の区別)
```

### セクション8｜片山まゆみについて

**比較**

| 案 | 特徴 |
|---|---|
| 写真あり | 人物への信頼感が出やすい。運営者主導のサービスであることが伝わる。 |
| 写真なし | 写真が未定の現時点でも進行できる。テキストと経歴の裏づけに集中できる。 |

**推奨**: 写真ありを本命として設計しつつ、写真が決まるまでの代替として、シンプルな図形(イニシャルや単色の枠)のプレースホルダーを用意しておく。経歴を長く載せず、本文は既存の3文構成のまま、プロフィールページへの導線を主役にする。

```text
┌───────────────────────────┐
│ [写真 or プレースホルダー]  見出し           │
│                        本文(3文)         │
│                        [片山まゆみについて見る] │
└───────────────────────────┘
```

## 10. CTAの配置と役割

## 11. 読みものへの導線
